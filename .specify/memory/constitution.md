# 元策 Spec Kit 项目宪章

本文件摘要项目的规格编写原则。完整优先级、工程约束、验证和运行流程以 `AGENTS.md`、`docs/standards/` 与具体 `docs/runbooks/` 为准；不得复制或放宽这些规则。

## 核心原则

### I. 规格描述业务结果

- `spec.md` 说明目标、用户场景、可验证的功能要求、边界和未决事项，不提前决定代码结构。
- 业务歧义只有在无法从用户要求或仓库事实可靠推导时才标为 `NEEDS CLARIFICATION`；不得用猜测替代必要决策。
- 对已存在的规格、计划和任务先读取再增量续写；稳定编号、完成状态和验证证据不可无故重置。

### II. 设计尊重现有系统边界

- `plan.md` 必须依据当前源码、接口契约和适用标准，说明方案、影响文件、依赖、风险及验证；不为配合模板臆造目录或架构。
- 先复用现有 API、共享前端、Web、Desktop 和部署模式。公共契约、数据状态、安全边界及跨模块变更须说明兼容与回归影响。
- 计划中的备选方案、研究、数据模型、接口合同和 quickstart 按需要生成，不强制创建无关文档。

### III. 验证匹配风险

- `tasks.md` 必须包含至少一项可执行的验证任务；验证可复用已有测试、构建、静态检查或手工运行证据，不要求每个任务都新增测试或默认 TDD。
- analyze、checklist、converge、任务勾选和主 agent 自评都不能替代代码审查、聚焦测试或真实集成验证。
- 安全、数据一致性、高风险接口与跨模块行为应扩大验证范围；重要改动按 `AGENTS.md` 记录独立复核。

### IV. 权限与运行环境有明确边界

- 用户当前指令和仓库规则优先于 Spec Kit Skills、模板、hooks、扩展及生成内容。
- 默认不切换或创建 Git 分支、不创建 PR 或外部工单、不跨模型调用、不连接共享环境、不执行数据库迁移或部署。按 `AGENTS.md` 与相关 Runbook 获取明确授权。
- 需求目录必须显式指定为仓库内 `specs/<feature>`；禁止依赖或写入共享活跃指针，禁止初始化覆盖已有产物。

## 工作流

- 中型及以上功能：`specify -> clarify（按需） -> plan -> tasks -> analyze -> implement -> converge`。
- 小修改可直接实施并聚焦验证；Bug 先复现和定位，范围扩大时再转规格流程。
- 收敛后仍执行独立 review、真实验证、Git diff 检查和当前工作分支的小闭环提交。

## 治理

- 需要修订宪章时，先更新 `AGENTS.md` 或相关项目标准，再同步本摘要。
- 上游受管理的 Skill、脚本、manifest 和模板不得手工编辑；本地差异放在 `.specify/templates/overrides/`、`AGENTS.md` 与 Runbook。
- 迁移计划、历史 brainstorm 和历史 plan 仅作来源证据；旧文档与当前源码或运行事实冲突时，不以过期描述覆盖当前事实。
