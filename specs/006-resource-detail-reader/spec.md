# 资料详情页阅读与操作体验

状态：规格完成
来源：用户反馈（资料详情页 UI 优化）；当前实现 `frontend/packages/app-shell/src/app.jsx`、`frontend/packages/app-shell/src/application.css`

## 目标与范围

优化项目资料详情页，使用户能快速返回资料库、辨认当前资料，并在阅读正文时更容易扫描长文、表格及章节目录。编辑应是清晰的常用操作；归档和保险箱密码重置属于低频管理操作，不应与阅读和编辑争夺同等视觉权重。

本需求覆盖资料详情页的页面层级、导航和操作入口、正文阅读宽度与响应式布局。保留现有正文、附件、左侧章节目录、权限、锁定资料、编辑与归档业务逻辑。不修改资料内容、API、数据库、共享登录态或其他页面。

## 用户场景与验收

### US1：阅读项目资料

- 优先级：P1
- Given：用户打开一条可访问的项目资料
- When：用户查看长篇正文、章节目录、表格或代码块
- Then：页面标题与资料元信息易于识别，正文具有适合阅读的行宽；目录跳转、目录宽度调整、正文滚动、图片和附件交互保持可用
- 关键失败或边界场景：正文无章节、正文开头已有与资料同名标题、资料受密码保护、正文包含宽表或长代码行、窄屏视口

### US2：返回或管理资料

- 优先级：P1
- Given：用户位于资料详情页
- When：用户要返回资料库、编辑资料或执行低频管理操作
- Then：返回入口位于页面左上方；有权限的用户能明显找到编辑入口；归档和保险箱密码重置不会冒充主要阅读操作，且仍受现有权限和状态限制
- 关键失败或边界场景：无编辑权限、已归档资料、资料锁定中、保存或附件上传期间、归档确认取消

## 功能要求

- FR-001：详情页必须在左上方提供返回资料库的可见入口；返回路径保持当前项目语境，点击后仍由现有应用路由处理。
- FR-002：资料标题、类别及归档状态（如适用）必须形成清晰、紧凑且不互相争抢的阅读页头；不显示可能与正文版本日期混淆的系统修改时间；同一标题不得在页面框架和正文起始处造成明显重复展示。
- FR-003：编辑资料作为有权用户的主要管理操作；归档作为编辑旁边可见的次级按钮，超级管理员的保险箱密码重置保持现有授权、确认和状态逻辑，并可直接触达。
- FR-004：正文与左侧目录继续独立滚动；目录定位、宽度拖拽和持久化、正文章节链接、附件预览/下载和解锁流程不得回归。
- FR-005：长段落需控制阅读行宽；表格与代码块可以在自身范围横向滚动，不得撑破页面或截断正文。
- FR-006：桌面、平板和手机宽度下，导航、标题、元信息和操作均不得重叠、溢出视口或导致布局跳动；窄屏操作仍可触达。
- FR-007：无权限、已归档、锁定、加载失败及操作反馈等现有状态必须继续正确呈现；不因样式变化绕过禁用状态或权限判断。

## 成功标准

- SC-001：在 1440px 及以上桌面视口、1024px 平板视口、390px 手机视口下，页头控件无互相遮挡，正文与目录仍能分别滚动。
- SC-002：现有资料详情目录、章节跳转、锁定资料和附件相关浏览器测试通过；标题同名、空目录和宽内容边界仍可使用。
- SC-003：使用正式环境 API 的本地预览能打开目标资料并完成只读浏览；本次验收不对正式资料执行写操作，也不将该预览视为正式环境发布。
