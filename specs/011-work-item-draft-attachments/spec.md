# 新建工作项附件无需标题（草稿附件暂存）

状态：实施中
来源：用户反馈（2026-11-16 会话）——“之前就有说不要有这个标题的限制”；历史提交 `6fbec518`（仅把报错改为等待标题，未真正解除限制）、`09b1fc16`（等待态提示）。

## 目标与范围

新建需求 / 任务 / Bug 弹窗中，用户在填写标题之前即可通过粘贴、拖拽或工具栏「附件」按钮上传图片、视频和文件，上传立即开始并完成，不再等待标题，也不再为了挂附件提前创建工作项。

范围：

- 新建工作项弹窗的“说明内容”富文本编辑器。
- 后端提供不依赖工作项的“草稿附件”暂存能力，并在创建工作项时把草稿附件绑定到新工作项的主帖。
- 未被创建绑定的草稿附件按期自动清理（数据库记录与对象存储对象）。

不做：

- 不改变已存在工作项详情、评论、项目资料的上传链路。
- 不取消“创建工作项必须填写标题”的提交校验；只解除“上传附件依赖标题”的限制。
- 不改变对象存储直传、加密与签名机制。

## 用户场景与验收

### US1：未填标题时直接上传附件

- 优先级：P1
- Given：用户在项目中打开“新建需求”（或任务、Bug）弹窗，标题为空
- When：粘贴图片、拖入文件或点击「附件」选择文件
- Then：附件立即开始上传并完成，编辑器内显示可预览的图片 / 视频或文件卡片；期间不创建任何工作项，列表中不出现草稿工作项
- 关键失败或边界场景：上传失败可重试或移除；对象存储未激活时给出明确错误；无项目写权限时拒绝。

### US2：创建后附件归属新工作项

- 优先级：P1
- Given：说明内容中已有一个或多个上传完成的草稿附件
- When：填写标题并点击「创建」
- Then：工作项创建成功，主帖正文中的附件指向新工作项主帖下的附件，详情页可正常预览 / 下载；附件 id 不变
- 关键失败或边界场景：正文引用了他人的、其他项目的、已删除的或未上传完成的草稿附件时拒绝创建；创建失败时草稿附件保持可用，可再次提交。

### US3：放弃新建时不留垃圾

- 优先级：P2
- Given：用户上传了草稿附件
- When：取消新建弹窗，或在编辑器中移除附件
- Then：不产生工作项；被移除的附件立即删除；遗留的草稿附件在过期后由清理任务删除数据库记录并排队删除对象存储对象

## 功能要求

- FR-001：后端提供项目级草稿附件接口：登记、获取上传签名、确认上传、获取下载签名 / 预览、删除；仅草稿上传者本人可访问，且要求对该项目有创建工作项的权限。
- FR-002：草稿附件与已有附件使用同一套 `file_objects` / 对象存储 / 加密机制，object key 生成方式不变。
- FR-003：创建工作项接口接受正文中引用的草稿附件，在同一事务中创建工作项与主帖，并把被引用的草稿附件原地改绑到主帖（附件 id 不变），正文中草稿附件 URL 规范化为主帖附件 URL。
- FR-004：创建时校验被引用草稿附件：属于当前用户、属于同一项目、已上传完成、仍为草稿；任一不满足则整体拒绝且不产生副作用。
- FR-005：新建弹窗上传附件不再依赖标题，不再提前创建工作项（移除 checkpoint 与「转到详情」分支）。
- FR-006：编辑器中移除尚未创建的草稿附件时调用删除接口。
- FR-007：草稿附件超过保留期（默认 24 小时）未绑定时，由现有文件清理命令软删除并排队删除对象存储对象。
- FR-008：草稿附件的图片 / 视频 / 文件在编辑器内可预览或下载。

## 成功标准

- SC-001：本地 e2e：标题为空时上传附件立即发起登记与直传请求，并完成；创建后正文附件指向主帖附件，详情页可见。
- SC-002：API 集成测试覆盖草稿登记→上传→创建绑定、越权（他人 / 他项目）拒绝、未上传完成拒绝、删除与过期清理。
- SC-003：已有评论附件、主帖附件、粘贴上传相关测试保持通过。

## 风险与验证要求

- 数据一致性：`file_attachments.target_type` 新增 `draft` 需重建表的迁移，必须保留现有数据、索引与约束；迁移需在测试库与正式库副本上验证。
- 安全：草稿附件访问必须限定上传者本人；绑定校验防止引用他人附件。
- 清理：过期草稿走现有删除任务，避免直接删除仍可能在途的 PUT。
- 验证层级：Rust 单元 / 集成测试、前端单测、Playwright e2e（真实接口，测试存储），独立代码复核，复核记录写入 `docs/reviews/`。
