# API 严格 Clippy 告警清理

状态：实现及验收完成，未部署
来源：用户要求清理剩余告警；docs/reviews/2026-10-08-resource-followup-review.md

## 目标与范围

清理当前 API 全目标严格 Clippy 的剩余告警，恢复可用的质量门禁。覆盖被告警定位的 API 源码及测试，保持现有用户可见行为、HTTP 契约、数据库结构与安全边界。本次不部署，不修改生产资料，不清理其他工具链或无关模块。

## 用户场景与验收

### US1：开发者可执行无告警的质量检查

- 优先级：P1
- Given：当前 API 严格检查因既有告警失败。
- When：开发者执行全目标质量检查与相关回归。
- Then：检查通过，原有授权、文件加密、资料保存与会话行为保持一致。
- 关键失败或边界场景：浮点 NaN 不可被当作合法工时；SQL绑定顺序、加密参数和错误分支不得因整理改变。

## 功能要求

- FR-001：消除当前 API 全目标严格检查告警，不全局放宽 lint，不通过隐藏告警代替修复。
- FR-002：调整内部参数组织时，保留原值、调用顺序、事务边界和错误语义，不修改外部请求/响应协议。
- FR-003：保留资料容量及章节引用、附件引用与版本保护、会话和文件加密行为；执行匹配改动的实际回归。
- FR-004：完成独立审查并记录验证结果、剩余问题与未部署状态。

## 成功标准

- SC-001：API 全目标严格 Clippy 成功退出，无告警。
- SC-002：API 测试及 CLI 契约回归通过，无本轮新增失败。
- SC-003：独立审查无未解决阻断问题，改动按当前分支提交推送；未部署。

## 风险与验证要求

告警含多模块控制流、参数过多、类型复杂与浮点比较。机械修正必须核对差异；参数调整核对所有调用点；复用 API 单元/集成测试、文件加密/会话与 CLI 契约测试。独立审查重点检查授权、事务、SQL绑定、NaN及加密参数。
