# 测试效率与正确性优化

状态：已完成
来源：用户需求（2026-11-20 会话）——“进行所有测试优化，保证测试正确性的前提下，优化测试效率，提升开发效率”。

## 目标与范围

在不降低覆盖与断言强度的前提下，缩短本地开发中最常运行的测试与检查耗时，并修复导致测试结果不可信的问题（长期失败、并行互相干扰、过时断言）。

范围：

- Rust：`yuance-api`、`yuance-agent` 的单元测试与集成测试。
- 前端：`frontend`（5 个包）与 `web` 的源码约束、类型检查、lint、单元测试。
- 脚本测试：`scripts/test/*.test.cjs`。
- 浏览器 e2e：`web/e2e`（Playwright），含视觉回归配置。

不做：

- 不删除测试用例、不放宽断言来换取速度；确需调整的断言须对齐当前产品行为并保留原测试意图。
- 不引入新的外部 CI；不改变正式部署流程。

## 用户场景与验收

### US1：后端改动后快速得到测试结果

- Given：修改一处后端代码
- When：执行 `cargo test -p yuance-api`
- Then：重新编译与运行总耗时明显低于优化前，用例数量与结果不变

### US2：前端提交前检查更快

- Given：修改前端代码
- When：执行 `npm run check:frontend` 或各自 `npm run check`
- Then：执行全部原有检查项，耗时明显缩短；任一项失败时整体失败并给出该项输出

### US3：e2e 结果可信且更快

- Given：执行 `npm --prefix web run test:e2e`
- When：全部用例运行
- Then：不再因并行用例共享数据而随机失败；长期失败的用例被修复；总耗时明显缩短

## 功能要求

- FR-001：Rust 依赖在开发 / 测试构建中启用优化（工作区代码保持 debug），消除 argon2 等依赖在 debug 下的极端耗时。
- FR-002：Rust 集成测试合并为单一二进制以减少链接次数并统一并行调度；会修改进程环境变量的测试保持独立二进制。关闭无内容的 doctest 与二进制测试目标。
- FR-003：前端与 web 检查改为并行执行全部原有检查项，任一失败即整体失败；各包 eslint 缓存互不覆盖。
- FR-004：e2e 每个 worker 使用独立服务与独立数据库（模板库副本），开启 fullyParallel；前置步骤（当前项目、对象存储）通过接口准备。
- FR-005：修复长期失败的测试（Spec Kit 版本断言、e2e 过时断言、缺少 CLI 构建产物等），并记录根因。
- FR-006：更新相关 Runbook，说明新的测试入口、并行与隔离约定。

## 成功标准

- SC-001：同一台机器、相同负载条件下，各测试入口优化前后耗时对比记录在复核文档中。
- SC-002：Rust、frontend、web、scripts 测试数量与优化前一致且全部通过。
- SC-003：e2e 全量通过（或仅保留经说明的已知问题），无并行干扰导致的失败。

## 风险与验证要求

- 合并测试二进制可能暴露进程级全局状态冲突：保留修改环境变量的测试为独立二进制，并多次运行验证稳定性。
- 并行执行器须正确传播失败：以故意失败的用例验证。
- e2e 隔离后同一 worker 内用例仍共享数据：前置步骤改为接口准备，避免依赖列表分页等易变状态。
- 独立代码复核，结论写入 `docs/reviews/`。
