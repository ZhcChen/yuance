# 上传与清理契约

## 上传完成

- 所有附件 PUT 签名只针对 `pending` 状态签发，且请求必须带服务端返回的全部签名头。
- 已签发的 PUT URL 是一次性对象创建能力；重复 PUT 不覆盖已有对象。阿里云 OSS Bucket 必须关闭版本控制。
- 完成接口服务端核对对象真实长度、Content-Type 和 SHA-256。普通明文附件创建时若已提供 `checksum_sha256`，完成时必须与实算明文摘要一致；加密资料附件完成请求 `encrypted_sha256` 必须等于服务端实算密文摘要。`checksum_sha256` 仍表示明文摘要，服务端不以密文摘要代替；CLI 解密时校验密文头、明文大小和实际明文摘要。
- 完成响应只有在 `data.status == "uploaded"` 时视为成功。相同对象摘要的完成重试幂等成功；不同摘要返回冲突。
- 系统发布资产使用独立契约，完成时服务端实算 SHA-256 必须匹配创建时登记的 manifest SHA-256，且只能由 pending 转为 uploaded。
- 上传签名 URL 不附带 `access` 查询参数，也不接受受保护资料访问 token。列表和下载 URL 仍按资料访问契约传递 token。
- 签名 `expires_in_seconds` 的服务端范围为 60–3600。`If-Match` 不用于 `/uploaded`；资料附件删除需提供 `If-Match: resource.updated_at`。

## 附件对象删除与维护

- 资料附件删除 API 原子地执行正文引用检查、`If-Match` 检查、逻辑删除与 outbox 任务登记。评论附件删除在同一事务移除正文引用、更新主帖摘要并登记任务；取消评论草稿先软删评论，再为无其他保护性附件关系引用的对象登记任务。系统发布资产单项删除和保留裁剪在事务内解除资产关系，并为无其他保护性附件关系引用的对象登记任务。
- 为避免仍有效或已被 OSS 接收的旧 PUT URL 在删除后重新创建 OSS 对象，签名成功后会在数据库记录其最大有效期；逻辑删除与读取该有效期在 SQLite 写事务中串行，任务至少延迟至最后签名过期后 4 小时 5 分钟，且不少于删除后 65 分钟。4 小时覆盖 OSS 单次 PutObject 请求时限，额外 5 分钟作为余量。签名在删除提交后完成的请求不能返回 URL。API 立即返回逻辑删除结果，不立即物理删除。
- 迁移前已有文件对象无法恢复旧签名的精确到期时间；迁移将其保守设置为迁移时刻后 1 小时，使其后续删除最早等待到迁移后 5 小时 5 分钟。
- PUT 返回非成功状态或网络错误时，CLI 将结果标记为不确定并返回附件 ID；加密流已完整生成时附同一密文摘要，供读取状态后执行完成确认。无法取得摘要时不得猜测或重发 PUT。
- 管理员运行 `yuance-api files cleanup-deleted --dry-run` 查看安全窗口内和到期任务，再运行 `yuance-api files cleanup-deleted --limit N` 处理到期任务。命令不能强制绕过安全窗口。
- 处理失败后运行 `yuance-api files deletion-jobs --limit N` 查看未完成任务的状态、重试时间和截断错误信息。
- 临时失败不恢复附件可见性，也不丢失清理任务；任务使用 lease token 防止过期 worker 写回。
- 清理按任务快照的原 provider/endpoint/region/bucket/key 执行。任务未能确认原位置时保留失败状态，不能将其他 Bucket 的 NotFound 当作成功。
- 生产 OSS Bucket 必须关闭版本控制；`DeleteObject` 成功在开启版本控制的 Bucket 上可能只添加删除标记，清理任务完成不代表历史版本已物理清除。
- 项目附件删除仍是逻辑归档，不生成 OSS 清理任务。资料附件删除保留正文引用和 If-Match 校验；评论/系统发行资产删除不会删除仍被其他保护性关系引用的共享对象。
- 目标 `file_object_id` 若仍被其他保护性关系引用，资料附件删除会冲突；同一逻辑删除重试不会重复创建任务。软删除但可恢复的工作项关系仍属于保护性引用。
