# 附件上传与删除一致性

状态：实现已完成，独立复核中
来源：`docs/reviews/2026-10-09-full-project-audit.md`

## 目标与范围

修复附件对象存储与数据库状态之间的完整性缺口，使已完成附件不被重复上传签名覆盖，完成登记的摘要对应实际对象内容，并确保对象删除失败后仍能安全重试。范围包括共享附件上传/完成路径、资料附件、评论附件、系统发布资产的物理删除路径、对象存储适配层、SQLite 持久化状态、CLI/OpenAPI/yuance-agent Skill 契约与隔离测试。

不重新加密或改写既有附件，不清理未经审计的历史对象，不改动用户资料正文，不访问正式环境，不执行正式对象删除或部署。

## 用户场景与验收

### US1：上传完成后保持附件对象不可变

- 优先级：P1
- Given：附件对象处于 `uploaded` 状态，或同一附件的上传完成登记正在并发处理
- When：客户端再次请求上传签名、重放上传或重复提交完成登记
- Then：已确认对象不会被新字节覆盖，数据库中的状态、大小、摘要和加密元数据保持与已确认内容一致
- 关键失败或边界场景：旧预签名 PUT 在有效期内被重放；两个完成登记并发；完成登记收到格式合法但与对象内容不符的摘要

### US2：完成登记只接受与实际对象一致的元数据

- 优先级：P1
- Given：明文或加密附件对象已写入隔离对象存储
- When：客户端调用上传完成接口
- Then：服务端校验对象实际大小、Content-Type 及可验证的 SHA-256，并仅原子地把 `pending` 转为 `uploaded`
- 关键失败或边界场景：对象不存在、存储暂时不可用、错误摘要、加密密文摘要与明文摘要混淆、数据库状态更新影响行数为零

### US3：对象删除失败后可重试收敛

- 优先级：P1
- Given：用户删除一个未被正文引用的已上传附件
- When：数据库变更成功而 OSS 删除失败或超时
- Then：系统保留可持久重试的对象清理线索；后续维护重试成功后可确认任务完成
- 关键失败或边界场景：对象已不存在、重复请求、进程在数据库提交与 OSS 删除之间退出、清理重试期间发生新的请求

### US4：API、CLI 和 Skill 使用一致的上传/恢复契约

- 优先级：P2
- Given：AI 或 CLI 执行附件上传、完成登记和失败恢复
- When：使用当前 OpenAPI 与 Skill 示例调用
- Then：必填字段、有效期边界、摘要语义及重试步骤与服务端一致，上传 URL 不携带无效的访问凭证
- 关键失败或边界场景：PUT 成功但完成请求响应丢失；客户端仅能回读附件状态；OpenAPI 声明范围与服务端范围不一致

## 功能要求

- FR-001：上传签名只可用于状态为 `pending` 的附件；`uploaded` 或 `deleted` 附件不得再次取得指向同一最终对象的 PUT 授权。
- FR-002：完成登记必须原子地要求附件对象当前状态仍为 `pending`；重复或并发登记不得静默报告成功，也不得覆盖已登记的大小、摘要或加密信息。
- FR-003：完成登记必须依据对象实际内容验证 SHA-256。加密资料附件使用实际密文摘要，并与请求中的 `encrypted_sha256` 比较；明文附件使用实际明文摘要，并与创建时非空的 `checksum_sha256` 比较。加密资料附件的 `checksum_sha256` 是明文摘要声明，客户端解密时仍须与密文头及实际明文校验；服务端不将密文 SHA-256 冒充为明文校验结果。
- FR-004：若对象存储不能提供可信 SHA-256 元数据，服务端必须以可取消的流式读取计算实际摘要；单文件明文上限为 1 GiB，加密密文上限按现有格式头部开销计算。对象超限、读取失败或超时不得改变附件状态。
- FR-005：已完成对象必须免受已签发 PUT URL 的有效期内重放影响；使用对象存储条件写入拒绝覆盖，并明确阿里云 OSS 在版本控制开启或暂停时该条件不生效，相关 Bucket 必须关闭版本控制。
- FR-006：资料附件、评论附件及系统发布资产的物理删除在数据库与对象存储之间保留持久、幂等、可重试的清理任务；任务最早执行时间不得早于逻辑删除后 65 分钟，也不得早于删除前最后一张上传签名 URL 到期后 4 小时 5 分钟，以覆盖 OSS 已接收且在 URL 到期时仍进行中的 PUT 请求。存储删除失败或 API 进程中断不得丢失对象键、原存储配置定位信息及后续重试线索。项目附件仍只执行归档，不进入物理删除任务。
- FR-007：对象不存在应视为幂等删除成功；暂时性存储错误保留重试；任务完成状态不得早于原存储位置上的对象删除确认。重试不得因活动 Bucket 已切换而在错误 Bucket 的 NotFound 上误报完成。
- FR-008：资料附件删除任务不得绕过资料正文引用冲突保护和 If-Match 版本校验；评论附件删除必须在事务内移除正文引用并检查其余保护性引用，系统发布资产删除必须在事务内移除资产关系并检查其余保护性引用。文件对象仍被其他保护性附件关系引用或版本冲突时不得将共享对象标记删除或创建任务；软删除但可恢复的工作项附件仍属于保护性引用。同一附件重复 DELETE 可返回 NotFound，但不得重复创建任务；对象任务唯一约束保留既有清理线索。
- FR-016：恢复软删除工作项时，必须在与附件删除任务创建互斥的事务中检查附件对象；若关联对象已标记删除或存在未完成清理任务，则以冲突拒绝恢复，避免重新激活指向已删除或即将删除对象的附件关系。
- FR-009：项目、资料、工作项、评论附件和系统发布资产的 PUT 都必须具备防覆盖条件写入。前四类附件共享 pending 状态和服务端实算摘要不变量；系统发布资产保留专用完成契约，但完成时实算摘要必须匹配创建时登记的 manifest SHA-256，且只能从 pending 转为 uploaded。系统发布资产单资产删除和版本裁剪也进入通用文件对象删除任务。
- FR-010：OpenAPI、CLI 和 yuance-agent Skill 必须准确描述摘要、有效期、上传完成及失败恢复契约；上传签名请求不得发送未被服务端使用的访问 token。
- FR-011：既有加密附件、历史明文附件、受保护资料访问、SVG 静态安全校验、项目附件仅归档语义、评论附件删除后的正文/主帖摘要同步和客户端解密行为不得回归。
- FR-012：自动化测试必须使用隔离数据库和测试对象存储，覆盖旧签名重放、错误摘要、并发完成、删除失败重试和对象不存在；不得连接正式存储。
- FR-013：资料附件删除前必须确认目标 `file_object_id` 没有其他未删除关系引用；遇到共享对象时拒绝删除，不得影响其他关系读取。
- FR-014：所有已登记文件对象的上传签名、完成校验、下载签名、读取和删除均使用 `file_objects.storage_config_id` 绑定的存储配置，不得回退至当前活动配置；原配置缺失或凭证不可用时显式失败。
- FR-015：执行历史上传签名有效期回填的正式部署必须先按目标机 `.env` 的 Compose 配置优雅停止旧 API，再从 Compose `./data:/data` 的宿主机挂载源生成唯一生产数据库 `sqlite:///data/yuance.sqlite3` 的必须成功快照，然后执行迁移；必需模式只允许 `$APP_DIR/data/yuance.sqlite3`，不得回退到宿主机 `/data/yuance.sqlite3`。生产 `YUANCE_DATA_DIR` 只能为空或 `/data`，进程环境中的 SQLite、数据目录与备份路径覆盖必须清除。外层停止超时按优雅停机值加 60 秒计算，只有显式发布参数可覆盖目标机配置。数据库缺失、数据库 URL/数据目录/宿主机挂载源不匹配、快照失败或迁移失败时不得继续启动新 API；迁移前收到中断信号时尝试恢复原本运行的 API，迁移阶段开始后失败则 API 保持停止，除非先恢复匹配的数据库备份或继续部署兼容的新版本。迁移程序仅在环境解析、数据库连接及迁移历史校验成功后，紧邻调用迁移器之前创建并同步部署阶段标记；该标记表示迁移阶段即将执行，不代表数据库已发生修改，因此标记写入后的窄中断窗口也保守保持 API 停止。维护容器未启动、`migrate status` 失败或 `migrate up` 前置校验失败且标记不存在时，部署脚本恢复原本运行的 API。若 Compose 环境提供 `YUANCE_FILE_MASTER_KEY`，快照须使用同一值并记录为外部配置来源；快照对 `.env` 中 `=` 和 `:` 两种赋值格式的解析须与 Compose 一致。部署脚本的本地 WSL 与远程路径均遵守此顺序，并有回归测试锁定。当前部署脚本未实现同一 Docker Engine 上的并发发布互斥，所有发布者必须串行操作同一目标；共享可变 `latest` 标签期间禁止另一发布或手工维护任务并行运行。
- FR-017：`files cleanup-pending` 将旧 `pending` 对象标记为 `deleted` 前，除创建年龄门槛外，还必须等待最后一张上传签名 URL 到期后 4 小时 5 分钟；从未签发签名的对象可按年龄清理，无法解析的非空有效期必须保留。dry-run 计数和实际更新使用相同条件，实际 `UPDATE` 必须重新检查有效期，避免与签名续期并发时提前失效对象。
- FR-018：`files audit-objects` 的 attached/orphan 统计必须把 `file_attachments` 与 `system_release_assets` 都视为文件对象所有者关系；仅由系统发行资产引用的对象不得被误报为孤儿。

## 成功标准

- SC-001：`uploaded` 与 `deleted` 附件再次请求上传签名时，服务端均拒绝，数据库和已确认对象内容保持不变。
- SC-002：对象字节、大小、Content-Type 或提交摘要任一不符时，附件均不能变为 `uploaded`，错误元数据不会持久化。
- SC-003：并发完成登记最多有一个状态转换成功；其他请求得到稳定、可诊断的冲突或幂等响应。
- SC-004：逻辑删除后至少 65 分钟、且最后一张上传签名到期后 4 小时 5 分钟以内任务不会物理删除对象；该窗口覆盖 OSS 对单次 PutObject 的最长 4 小时请求时限及 5 分钟余量。测试通过隔离数据库验证正常和延长窗口，不使用真实等待。窗口过后注入一次对象删除失败，资料附件、评论附件和系统发布资产均保留持久清理任务；服务重启或显式清理重试仍能定位原 Bucket 并完成删除；对象已不存在时重复执行安全成功。
- SC-005：加密附件端到端上传、下载、解密、摘要校验测试通过；历史明文附件、SVG 安全校验和正文引用删除保护无回归。
- SC-006：OpenAPI 契约测试、CLI 请求测试及 Skill 命令说明与服务端验证一致；失败恢复不会重新 PUT 已完成对象，也不会把确定的摘要不匹配伪装成结果不确定。
- SC-007：系统发布资产摘要错误时保持 pending；摘要正确后完成，重复上传签名与对象覆盖均被拒绝，manifest SHA-256 语义保持不变。
- SC-008：活动 Bucket 从 A 切换到 B 后，A 中尚未完成的附件仍可在 A 完成确认；A/B 相同 object key 的对象不会串读、误删或误报 NotFound。
- SC-009：软删除工作项所关联的文件对象进入删除状态或存在未完成清理任务后，恢复工作项返回冲突且不清空 `deleted_at`；反向并发时，SQLite 写事务串行化保证清理任务不能越过成功恢复后的有效附件引用。
- SC-010：本地 WSL 与远程部署均从目标机 `.env` 安全解析 Compose 停机宽限期，按宽限期加 60 秒计算外层超时，并将解析值实际传给 Compose；显式覆盖生效，错误/重复/插值配置失败关闭。迁移和快照使用同一 `sqlite:///data/yuance.sqlite3` 与 `/data` 容器目录目标，宿主快照只接受 Compose bind mount 的 `$APP_DIR/data/yuance.sqlite3`，缺失数据库或数据库 URL/数据目录/宿主快照路径不匹配时不得迁移；继承的 SQLite、数据目录和备份路径不能改写快照目标，环境提供的文件主密钥必须与 Compose 使用同一值，`.env` 的主密钥 `=`/`:` 格式均能正确识别。维护容器启动失败、迁移状态预检失败或迁移前中断时，若旧 API 原本运行则尝试恢复；迁移阶段标记写入后失败时不自动恢复旧写服务。标记在迁移历史校验后、调用迁移器前创建并同步，标记后的中断按保守策略保持停机。部署要求同一 Docker Engine 上单发布者串行执行。测试不连接真实目标机。
- SC-011：隔离数据库中的旧 pending 对象在签名到期后 4 小时 5 分钟之前，dry-run 不计数且实际清理不改变状态；从未签名或安全窗已过的旧 pending 对象可清理；非空无效时间戳不会被当作从未签名。
- SC-012：仅由 `system_release_assets` 引用的文件对象在默认及包含已删除对象的盘点中均计为 attached 而非 orphan；`attached + orphan == total`，且 CLI 摘要与领域统计一致。

## 风险与验证要求

对象摘要验证会读取对象字节，须遵守 1 GiB 明文上限，流式读取并对每次读取设超时；读取失败不改变附件状态。对象删除重试需 SQLite 迁移、事务边界、幂等任务调度和维护审计；必须由独立 reviewer 复核。阿里云 OSS 条件写入的限制必须写入运维 Runbook，并保留真实 OSS 手工验证步骤。

验证覆盖 API handler 集成测试、共享 domain/storage 单测、迁移升级测试、CLI/OpenAPI 契约测试、加密附件传输测试及隔离 OSS 错误注入测试。静态分析和任务勾选不代替失败注入与状态回读。

## 未决事项

- OSS 条件写入和物理清理都要求关闭 Bucket 版本控制；本机隔离测试不能证明真实 Bucket 配置，必须在真实 OSS 手工验收中检查。运行时 `DeleteObject` 成功不代表版本化 Bucket 的历史对象版本已物理清除。
- 使用数据库 outbox 与显式维护命令处理资料附件、评论附件及系统发布资产删除重试；项目附件仍仅归档。
- 服务端附件单文件明文上限为 1 GiB；当前 CLI 的上传/下载安全上限是 128 MiB，下载会聚合至内存。本轮不提高 CLI 上限。
