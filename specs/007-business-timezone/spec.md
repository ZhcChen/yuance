# 东八区业务时间显示修复

状态：规格完成
来源：用户反馈元策时间显示不正确；已复现无时区 UTC 被当成本地时间及直接显示原值的问题。

## 目标与范围

Web 与桌面端的业务时间统一显示东八区的实际时刻，不受设备时区影响。涵盖资料列表、工作项详情/评论/流转/附件、通知、搜索、工作台、个人资料、管理页面及服务端桌面下载页的发布时间。保留数据库 UTC 与现有 API 字段，不修改历史数据或正文内用户编写的日期，不调整截止日期、周期日期、甘特图等纯日期字段，不部署。

## 用户场景与验收

### US1：准确阅读业务时间

- 优先级：P1
- Given：资料或工作项在 UTC 02:30 创建
- When：用户在东八区或其他设备时区打开业务页面
- Then：相应时间均显示东八区 10:30；历史无时区 UTC 与带偏移时间表示同一时刻时显示相同
- 关键失败或边界场景：跨天/跨年、毫秒、显式 +08:00、空值/非法值、纯日期、评论编辑时间与创建时间比较

## 功能要求

- FR-001：历史数据库格式的无时区时间按 UTC 解释，带 Z 或偏移的时间按其明确时区解释，再统一显示 Asia/Shanghai，不能重复加八小时。
- FR-002：共享前端的业务时间显示复用同一规则，包括原先直接透传的评论、附件、工作项及流转时间和工具提示。
- FR-003：纯日期和用户正文中的日期保持原值；空值和非法值不能导致页面抛异常。
- FR-004：数据库、鉴权/过期计算、排序、API 原始时间字段及写入数据保持兼容，不迁移或改写历史时间。

## 成功标准

- SC-001：2026-10-09 02:30:00、2026-10-09T02:30:00Z 和 2026-10-09T10:30:00+08:00 均显示东八区 10:30，在 UTC、东八区和美洲设备时区结果一致。
- SC-002：本地浏览器真实 API 的资料/工作项创建时间与东八区系统时钟吻合；截止日期原样显示；不操作正式资料。

## 风险与验证要求

测试不同宿主时区下的 UTC/偏移/无时区时间与跨日跨年、空值、纯日期。运行共享前端和 Web 检查、聚焦浏览器集成及既有资料/工作项回归；独立审查确认没有影响 API、持久化和鉴权时间。服务器明确标注 UTC 的诊断时间允许继续显示 UTC。

## 未决事项

无。东八区是用户明确的业务显示时区。
