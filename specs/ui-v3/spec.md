# 元策 UI v3 设计原型模块

状态：草稿
来源：用户需求（2026-11-04 对话）、仓库现状 `web/`、`frontend/packages/`、`docs/prototypes/time-management/index.html`

## 目标与范围

为「元策」项目管理协作系统重构一版 UI 设计，产出可独立评审的交互与视觉原型。

产出形态为仓库根目录下的独立模块 `ui-v3/`，技术约束为纯 HTML + CSS + 原生 JavaScript，零构建、零第三方依赖，数据使用静态 mock。

覆盖范围：工作台、项目列表与项目详情、需求/任务/Bug 列表、工作项详情、资料库、消息中心、全局搜索、个人中心、系统管理各子页。

明确不做：
- 不改动 `frontend/packages/`、`web/`、`desktop/`、`api/` 任何现有实现，不影响现网与既有视觉合同、e2e。
- 不重新设计「时间管理」页面内容（`/web/time-management`），该页面沿用当前实现；v3 仅调整其在导航壳层中的入口位置与外框呈现。
- 不接入真实后端 API，不做鉴权、持久化与真实文件操作。
- 本阶段不产出 React 回迁代码；设计定稿后需另立规格将设计回迁到 `frontend/packages/ui`。

## 用户场景与验收

### US1：设计评审者浏览 v3 原型（优先级 P1）

- 优先级：P1
- Given：本地已克隆仓库，用户知道如何启动静态服务
- When：在浏览器打开 `ui-v3/` 的本地服务地址，依次浏览各页面并切换导航
- Then：每个页面都能正常渲染，无控制台报错，页面间通过导航可互相跳转，视觉语言全局一致
- 关键失败或边界场景：直接以 `file://` 打开时原生 ESM 受 CORS 限制无法加载，README 必须给出正确启动方式

### US2：设计评审者对比 v3 与现网差异（优先级 P2）

- 优先级：P2
- Given：已同时打开线上现网与本地 v3 原型
- When：逐页对照信息密度、导航结构、层级与操作可达性
- Then：差异点可被清晰指出，且 v3 未遗漏现网已有的关键信息与操作入口

### US3：后续实现者依据原型回迁 React（优先级 P3）

- 优先级：P3
- Given：v3 设计通过评审
- When：依据原型实现 `frontend/packages/ui` 的组件与令牌
- Then：原型中的设计令牌、间距刻度、字号刻度、组件规格可被直接对应，无需重新推导设计规则
- 关键失败或边界场景：原型中若出现与现网数据结构不兼容的交互，需在回迁前标注

## 功能要求

- FR-001：`ui-v3/` 模块必须零构建、零第三方依赖，仅使用原生 HTML、CSS 与 ES Module JavaScript。
- FR-002：模块必须自带静态 mock 数据层，页面渲染不发起任何后端请求。
- FR-003：必须提供统一的应用壳层（导航、全局搜索、当前项目切换、账户入口），且各页面复用同一壳层。
- FR-004：必须覆盖工作台、项目列表与详情、需求/任务/Bug 列表、工作项详情、资料库、消息中心、全局搜索、个人中心、系统管理各子页。
- FR-005：设计令牌必须集中定义在独立样式文件中，至少覆盖颜色、间距刻度、字号刻度、圆角、阴影、动效时长与 z-index 层级。
- FR-006：字号必须使用模块化刻度（12/13/14/16/18/24），间距必须使用统一刻度，禁止在页面内散落硬编码值。
- FR-007：可交互元素必须具备可见的键盘焦点态，且 tab 顺序与视觉顺序一致。
- FR-008：正文与背景的对比度不低于 4.5:1，状态色不得仅靠颜色区分，必须同时带文字或图形标识。
- FR-009：必须响应 `prefers-reduced-motion`，关闭非必要动效。
- FR-010：必须适配 375 / 768 / 1024 / 1440 四档视口宽度，宽表须横向滚动而非撑破布局。
- FR-011：不得使用 emoji 作为图标，必须使用内联 SVG。
- FR-012：导航壳层中的「时间管理」入口必须指向现有页面，v3 原型内不提供时间管理页面的重设计版本。
- FR-013：必须提供 `ui-v3/README.md`，说明模块定位、启动方式、页面清单、设计约定与回迁路径。
- FR-014：必须记录设计决策来源（`ui-ux-pro-max` 检索结论与人工过滤理由），并标注被否决的方向。

## 成功标准

- SC-001：本地静态服务启动后，各主页面均可正常渲染，浏览器控制台无报错。
- SC-002：从任一页面可在 2 次点击内到达其他任一主导航页面。
- SC-003：设计令牌集中在单一文件，页面样式中不出现未登记的硬编码色值与间距值。
- SC-004：375 / 768 / 1024 / 1440 四档视口下无横向撑破、无元素重叠。
- SC-005：键盘 Tab 可遍历全部可操作元素，焦点始终可见。
- SC-006：现有 `make frontend-check`、`make web-build` 与既有测试全部保持通过（原型模块不参与生产构建，需确认其未被误引入构建链路）。

## 风险与验证要求

- 主要风险：原型与现网长期并存造成实现漂移。对策：README 明确「原型非实现」，定稿后另立规格回迁，回迁完成前原型不进入生产构建链路。
- 主要风险：原生 ESM 在 `file://` 下无法加载。对策：README 给出静态服务启动命令，并在模块首页给出提示。
- 验证层级：静态资源完整性检查（HTML/CSS/JS 引用路径可解析）、各页面渲染截图、响应式四档截图、控制台无错误、键盘可达性人工走查、对比度抽检。
- 需确认：原型模块不被 `web`/`desktop` 的 Vite 构建与 CI 收集，避免污染生产产物。
- 需确认：`docs/prototypes/time-management/index.html` 现有原型不受影响。
