# 资料长正文完整保存与重编辑

状态：实现与本机验收完成，未部署
来源：用户反馈 BI 项目 P260713090179 资料 19；章节标识背景见 specs/002-resource-chapter-links/spec.md。

## 目标与范围

移除资料正文固定字符数上限，使已保存正文可完整回读、修改和重存。覆盖 Web、External OpenAPI、CLI、纯文本与 HTML；保留清洗、资料保护和章节引用。不修改生产 BI 手册，不自动部署。传输与运行资源仍有有限容量，必须准确说明并合理报错。

## 用户场景与验收

### US1：维护包含中文、SQL 和章节引用的长手册

- 优先级：P1
- Given：长 HTML/纯文本正文，或提交低于旧上限但自动补属性后超过旧上限的历史资料。
- When：通过 Web、OpenAPI 或 CLI 创建、回读、修改注释并再次保存。
- Then：安全内容完整，章节标识及链接保留，正文不截断、不乱码，各入口行为一致。
- 关键失败或边界场景：传输容量超限明确拒绝且不写入；危险 HTML 仍清洗，权限及保护不放宽。

## 功能要求

- FR-001：资料创建及更新不得对正文设置固定字符数限制，HTML 与纯文本一致，不截断。
- FR-002：数据库正文和版本快照字段适合长文本；若现有类型满足要求则不做无意义迁移。
- FR-003：清洗及自动补属性不引入保存后无法重提交的业务字符限制；已存在合法章节标识保持稳定。
- FR-004：编辑器输入、提交、前端请求、OpenAPI 和 CLI 支持长正文并如实报告传输/响应容量边界。
- FR-005：HTTP 应用及网关保留资源保护，容量按字节定义，超限有明确错误；不得宣称无限。
- FR-006：保留 HTML 安全清洗、资料权限/保护、章节跳转及左侧目录；不擅自改生产内容。

## 成功标准

- SC-001：本机真实 API 验证超过 50,000 字符的创建、读取、编辑重存，含中文、长 SQL、多代码块、大量链接；回读完整。
- SC-002：复现提交少于 50,000 字符、服务端补属性后超过 50,000 的案例，重存成功且章节标识不丢。
- SC-003：Web 编辑器与 CLI 真实验证通过，传输超限测试及独立代码审查通过，发布状态明确。

## 风险与验证要求

执行后端聚焦/HTTP契约测试、前端检查、CLI验证和无头 Playwright 真实本机验收。检查正文与版本快照字段、代理配置；独立复核安全和容量边界。超限不得发生部分写入。容量内真实回读与章节点击是运行验收，结构检查不能替代。

## 未决事项

无。技术容量由当前链路事实及资源保护确定并记录，正式部署须后续明确授权。
