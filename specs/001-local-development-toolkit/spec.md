# 本地开发套件与 Docker 隔离

状态：已实现并验收，待交付
来源：用户要求清理本地开发对远程 Docker 的依赖并规范开发套件；现有入口 `scripts/local-validation.sh`。

## 目标与范围

开发者可从本机完成依赖准备、独立开发库初始化、API/Web/Desktop 开发和容器验收。本地 Docker 操作只连接本机引擎，不能因当前 context、builder 或环境变量而操作远程主机。正式部署目标、运行服务及发布规则保持原有授权边界；本任务不部署、不更改用户全局 Docker 配置、不删除其他项目的 context 或缓存。

## 用户场景与验收

### US1：从零开展本地开发

- 优先级：P1
- Given：仓库已检出，开发工具已安装。
- When：开发者诊断、安装依赖、初始化并启动开发服务。
- Then：本地管理员可以登录，Web 和 Desktop 连接独立本地 API，状态和凭证不会覆盖正式数据。
- 关键失败或边界场景：依赖缺失、端口冲突、远程地址或继承正式密钥均不能静默继续。

### US2：只使用本机 Docker 验证镜像

- 优先级：P1
- Given：本机引擎可用，环境可能残留远程 Docker 配置。
- When：构建、启动、查看或停止本地镜像及容器。
- Then：操作固定到可核验的本机端点和构建器；原生架构镜像可健康运行，停止后保留开发数据。
- 关键失败或边界场景：远程端点或构建器必须在操作前拒绝，不自动回退到共享主机。

## 功能要求

- FR-001：统一开发命令提供 doctor、setup、prepare、seed、api、web、desktop、status 和 check；原生开发不强制依赖 Docker。
- FR-002：本地 Docker 命令校验本机端点并显式绑定 context 和对应本机构建器，隔离环境变量，且不修改全局选择。
- FR-003：提供原生架构和 AMD64 本机构建入口，以及开发容器启动、停止、日志、状态和镜像验收入口。
- FR-004：开发数据库、容器数据和本地验收副本彼此隔离；独立持久化 session、storage 和 file 密钥，不打印或继承正式密钥。
- FR-005：服务默认仅监听 loopback；拒绝非本地地址、非法端口和端口重叠。容器自动 local-admin seed 仅作用首次空开发库，失败支持重试；原生 seed 仅显式执行并说明会重置开发账号，旧验收入口不自动修改导入用户。
- FR-006：文档和 Make/npm 入口统一；保留正式部署与历史记录，旧验收入口继续可用。

## 成功标准

- SC-001：按开发 Runbook 可从独立空目录启动 API、登录开发管理员并通过健康检查。
- SC-002：真实本机构建和容器健康检查通过；停止再启动后数据库与密钥保留。
- SC-003：测试证明远程 Docker context/builder 和非本地服务地址被拒绝，已有全局 context 不被改写。
- SC-004：本地套件无远程主机硬编码；活动开发文档可定位唯一入口。

## 风险与验证要求

新增聚焦失败场景测试，真实本地容器 build/seed/health/login/restart 验证，原生开发环境验证。独立审查 Docker 隔离、持久化密钥及种子数据边界。Desktop 不需打开 GUI 验证；实际桌面交互作为未验证项注明。
