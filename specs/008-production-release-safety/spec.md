# 正式发布安全

状态：已完成
来源：本轮全项目审查；`docs/runbooks/production-deployment.md`；`docs/runbooks/api-migrations.md`

## 目标与范围

让正式发布在目标、参数或恢复备份不明确时尽早失败，避免部署到错误位置、使用不一致的 SQLite 文件回滚，或恢复后丢失附件解密能力。范围限于发布入口、发布前备份及相关手册和自动验证。

本需求不执行正式发布、不读取正式环境密钥、不改变已发布迁移、不自动清理备份，也不调整生产数据。环境变量提供的密钥由受控配置单独恢复，不复制到普通备份目录。

## 用户场景与验收

### US1：发布人员显式选择发布目标和构建方式

- 优先级：P1
- Given：发布人员从干净且与远端同步的 `main` 工作区启动正式发布
- When：未显式提供部署模式、构建模式或远程主机，或提供无效发布参数
- Then：脚本在 Git 网络访问、构建、传输、加载镜像、备份、迁移及服务重启之前失败，并指出缺少或无效的参数
- 关键失败或边界场景：显式选择历史 `local-wsl` 兼容模式仍须经过原有 WSL 和 Docker 检查；`remote` 模式必须指定目标主机；允许的参数边界值按运行手册定义

### US2：发布过程生成可验证的恢复备份

- 优先级：P1
- Given：正式环境已有使用 WAL 的 SQLite 数据库和文件加密密钥
- When：发布流程执行数据库备份
- Then：备份包含同一时点的一致 SQLite 快照；自动生成的文件主密钥随快照一同受限保存；备份完整性通过检查后才允许继续迁移
- 关键失败或边界场景：快照失败、完整性检查失败或自动生成密钥缺失时，发布必须停止在迁移之前；若密钥由环境变量提供，备份不得明文复制该值，并明确标记需从受控配置恢复

## 功能要求

- FR-001：正式发布脚本必须要求显式部署模式和构建模式；远程模式必须要求显式目标主机，不得以本地模式作为隐式默认值。
- FR-002：所有可在发布机提前校验的参数必须在 Git fetch、构建、SSH/SCP、镜像加载、备份和迁移等副作用之前校验。
- FR-003：正式发布备份必须使用 SQLite 支持的一致性快照机制，不得在数据库运行时逐个复制主库、WAL 和 SHM 并宣称其为一致快照。
- FR-004：自动生成的文件主密钥必须包含在同一受保护备份集中；备份目录权限不得宽于 `0700`，密钥和数据库快照不得宽于 `0600`。
- FR-005：使用环境变量提供文件主密钥时，不得将密钥写入普通备份；备份元数据和恢复文档必须说明依赖独立保存的环境配置。
- FR-006：数据库备份生成后必须执行完整性校验；备份命令失败或校验未通过时，迁移和服务替换不得开始。
- FR-007：部署手册、Easy Deploy README、回滚步骤及部署模板检查必须与显式参数和恢复备份格式一致。
- FR-008：自动化测试必须验证缺少/错误参数时脚本在 Git、Docker、npm、SSH 和 SCP 副作用前退出，并覆盖快照及密钥备份的成功和失败路径。
- FR-009：本需求不执行正式发布、数据库迁移、密钥轮换或正式数据恢复。
- FR-010：SQLite 备份收到 HUP、INT 或 TERM 时必须以非零状态退出，并清理未完成目录；不得继续写 manifest 或输出成功信息。
- FR-011：密钥来源判定必须遵循 Compose 环境变量优先级；无法可靠解析 `.env` 中的插值或转义时，备份必须失败关闭，不得漏备份数据文件密钥。
- FR-012：备份脚本不得修改任意既有父目录权限；仅限制本次备份目录和文件权限，并拒绝系统根目录、临时目录、应用数据目录及经符号链接解析后落入这些位置的备份根目录。
- FR-013：发布参数校验必须拒绝路径重复分隔符、无效或超长 Docker 镜像引用和物理路径落入运行目录的构建目录；远程构建须在上传源码归档前确认 `node`、`npm`、`tar` 可用且 Buildx builder 可初始化。

## 成功标准

- SC-001：部署模式、构建模式或远程主机缺失时，脚本在任何 Git 网络操作、构建、远程传输、镜像加载或数据库修改前以非零状态退出。
- SC-002：对启用 WAL 且有已提交写入的隔离测试数据库生成备份；恢复后通过 `PRAGMA integrity_check`，数据与备份时点一致。
- SC-003：使用自动文件密钥的隔离环境中，备份集包含权限受限的原密钥；恢复数据库和该密钥后可解密同一测试附件。
- SC-004：测试无效发布参数、快照失败、快照校验失败、缺少自动密钥和环境变量密钥配置时的失败语义，不报告虚假的备份成功。
- SC-005：正式部署和恢复文档中的示例与脚本参数、备份目录结构一致；不宣称已完成正式环境恢复演练。
- SC-006：隔离测试证明 TERM 中断不会产生成功备份；空环境变量覆盖非空 `.env` 时仍会归档数据文件密钥；不可解析插值失败关闭；既有备份根目录权限保持不变。
- SC-007：重复斜杠别名、构建目录符号链接别名、超长/非法镜像名和缺少远程 `tar` 在源码归档/传输/构建之前被拒绝；有效常见带 registry/port/tag 引用通过参数解析；远程 Buildx 初始化检查早于源码归档上传。

## 风险与验证要求

此改动触及发布脚本、容器镜像、SQLite WAL 和密钥恢复，需 shell 参数行为测试、隔离文件数据库快照/恢复测试、权限断言、部署模板校验、脚本语法检查及独立数据完整性复核。不得连接或改变正式环境；不得使用正式数据库或真实密钥作为测试输入。

## 未决事项

无。正式环境是否使用外置文件主密钥或已有独立密钥库属于环境事实；实现应显式记录外部密钥依赖，不假设正式配置。
