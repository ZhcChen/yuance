## 主要发现

### 必须修正的问题（均已修正）

- 写主帖不可安全重试：服务端已提交但响应丢失时，重试因草稿已改绑而一直失败。修正为“已绑定到同一主帖且上传者为本人”视为成功；新增测试 `primary_post_with_drafts_can_be_retried_after_lost_response`。
- 写主帖失败后点「转到详情」会丢失说明内容：修正为离开前补写一次主帖，仍失败则提示并需再次确认才放弃；新增 e2e 覆盖失败重试。
- 草稿地址识别范围过宽：正文文本 / 代码块中出现同名路径会被改写或导致保存被拒。修正为仅识别 `src` / `href` 属性值；新增测试 `draft_paths_in_plain_text_are_left_untouched`。
- 过期草稿几乎不会被自动清理、且 24 小时保留期可能误删长时间打开的弹窗中的草稿：改为登记新草稿时清理全站过期草稿，保留期 72 小时；`files cleanup-drafts` 写入 `docs/runbooks/file-maintenance.md`。
- spec / plan 与实现不一致（创建与写主帖为两次请求、checkpoint 仍用于失败重试、移除附件的删除时机）：已按实际实现更新。

### 可接受的残留项

- 预检用占位评论 id 0 改写正文，最终地址略长；正文接近长度上限时可能预检通过、终检超限，事务整体回滚，仅表现为保存失败提示。
- 正文中被删除的已上传草稿在提交或取消时才删除，而非移除节点当下；期间仅占用对象存储，最终由前端删除或过期清理兜底。

### 复核确认无问题的部分

- 授权：草稿接口与 Web 下载路由均要求项目访问，并按上传者 + 项目 + `draft` 过滤，他人 / 他项目一律 404；绑定校验上传者、项目与上传状态；写接口均校验 CSRF；用户无法自行指定 `target_type`。
- 事务：写主帖、改写、绑定、引用校验、摘要、活动与提及通知在同一事务，失败整体回滚。
- 迁移：保留全部列、约束与索引；无触发器 / 视图 / 外键引用 `file_attachments`。
- `draft` 计为受保护引用不影响既有删除路径（文件对象与附件一一对应）。

## 结论

可以部署。部署后需在正式环境做一次真实验收：新建需求时未填标题上传附件、创建后详情可见附件。
