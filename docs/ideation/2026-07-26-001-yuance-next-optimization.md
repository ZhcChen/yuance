# 元策下一阶段优化方向盘点

## 背景

基于当前仓库现状做的开放式盘点：

- 当前主应用集中在 `api/`，包含 Web、OpenAPI、系统管理、消息、资料库、周期、评论富文本、文档预览与系统版本管理。
- 根目录暂无 `app/`，说明 Flutter 多端模块仍未落地。
- `docs/solutions/` 目前只有 `.gitkeep`，说明经验沉淀体系还没开始形成。

## Grounding

### 代码与结构观察

- Web 与 API 路由已经比较完整，集中在 `api/src/web/router.rs`。
- 讨论实时能力和 typing presence 已存在，见 `api/src/platform/realtime.rs`。
- 工作项列表已经有统一表格与分页 partial，见：
  - `api/templates/web/partials/work_item_table.html`
  - `api/templates/web/partials/pagination_pages.html`
  - `api/templates/web/partials/pagination_size_jump.html`
- 项目资料库、周期、系统版本管理、OpenAPI token 管理都已入主流程。

### 现有计划中明确还没做或只做第一期的点

- 工作项批量操作仍属于后续增强，见 `docs/plans/2026-06-28-001-feat-yuance-v1-product-blueprint.md`
- 评论富文本第一期明确不做 `@提及 / 表情反应 / 图片标注`，见 `docs/plans/2026-07-13-001-feat-rich-text-discussion-plan.md`
- 周期能力第一期明确不做甘特图、燃尽图、依赖图等高级可视化，见 `docs/plans/2026-07-21-001-feat-project-cycles-plan.md`
- 资料库第一期不强制关联需求/任务/Bug，见 `docs/brainstorms/2026-07-13-project-resource-library-requirements.md`
- Flutter `app/` 模块目前只有规划，见 `docs/plans/2026-07-23-002-feat-flutter-app-module-plan.md`

## 建议优先级

## P1：最值得先做

### 1. 工作项“保存筛选视图 + 批量操作”

- **为什么值得做**
  - 这是现在最直接提升日常效率的点。
  - 你当前已经有统一列表、表格、分页、搜索，差的就是“批量处理”和“视图复用”。
- **建议内容**
  - 保存个人筛选视图
  - 默认视图 / 最近视图
  - 批量指派、批量改状态、批量改优先级、批量改周期
  - 批量归档/恢复（不做删除）
- **预期收益**
  - 管理者和执行人处理大列表时效率会明显提升。

### 2. 讨论协作增强：`@提及 + 草稿恢复 + 未处理提醒`

- **为什么值得做**
  - 当前讨论已经有富文本、回复、SSE、typing，但协作闭环还不够强。
  - 特别是 `@提及` 和草稿恢复，会明显改善多人协作体验。
- **建议内容**
  - `@提及` 指定人并写入消息中心
  - 评论草稿自动保存 / 页面刷新恢复
  - “我被提及”筛选
  - 回复未处理 / 超时未回复提醒
- **预期收益**
  - 讨论区从“留言板”升级为真正协作面板。

### 3. 资料库升级：标签 / 分类 / 关联 / 版本

- **为什么值得做**
  - 资料库已经能承载富文本和附件，但现在更像“帖子化资料”，还不够结构化。
  - 一旦项目资料多起来，检索和归档会很快成为痛点。
- **建议内容**
  - 标签、资料类型、收藏、归档状态
  - 与需求 / 任务 / Bug / 周期的可选关联
  - 资料版本历史
  - 最近访问、最近编辑、常用资料
- **预期收益**
  - 资料库会从“能存”升级成“好找、好用、能复盘”。

## P2：第二梯队

### 4. 周期面板升级：看板化 + 负载分析

- **为什么值得做**
  - 周期功能已经上线，但当前更偏“字段归属”，还不够管理友好。
  - 项目负责人最想看到的是某个周期下：待做、进行中、待确认、已完成的分布与节奏。
- **建议内容**
  - 周期视角看板
  - 周期内需求 / 任务 / Bug 分布
  - 周期成员负载热力图
  - 周期延期 / 堵塞提示
  - 周期完成率趋势
- **预期收益**
  - 项目推进会更可视，不再只靠列表阅读。

### 5. 系统级经验沉淀：把 `docs/solutions/` 真正用起来

- **为什么值得做**
  - 当前 `docs/solutions/` 为空，说明问题解决后没有形成复用知识。
  - 对后续 AI 协作、排错和交接都很关键。
- **建议内容**
  - 建立固定模板：问题、根因、改法、回归点
  - 每次线上 bug 或重要功能完成后沉淀一条
  - 与 MCP / Skill 文档互相引用
- **预期收益**
  - 后续开发、排查和 AI 接入质量会稳定很多。

### 6. OpenAPI / MCP 进一步产品化

- **为什么值得做**
  - 这块基础已经搭好，但还可以从“能接入”继续升级到“更好用”。
- **建议内容**
  - token 最近使用时间、最近调用摘要
  - scope 模板
  - 项目级 token 审计视图
  - MCP 常用任务 playbook（例如：分析某个项目、拉取待处理工作项、按周期汇总）
- **预期收益**
  - 让 AI 真的成为项目协作成员，而不只是能调接口。

## P3：战略性扩展

### 7. Flutter 多端 `app/` 模块

- **为什么值得做**
  - 这是产品形态扩张，不是当前 Web 的小优化。
  - 适合在 Web 核心协作体验稳定后启动。
- **建议内容**
  - 优先做消息、待办、工作项查看与评论
  - 再逐步补资料库、版本升级、离线缓存
- **预期收益**
  - 元策会从“项目后台”变成“随时协作工具”。

## 本轮未列为优先的方向

- 测试用例 / 测试计划模块：价值高，但会明显扩大产品边界。
- 复杂发布管理：当前已有系统版本管理，更建议先把项目协作主链路打磨完整。
- 甘特图 / 燃尽图：可以做，但当前优先级低于“批量操作、讨论闭环、资料结构化”。
- legacy `doc/ppt` 预览继续深挖：投入产出比不高。

## 当前建议结论

如果只选 **3 个最值得立刻继续做** 的方向：

1. 工作项保存筛选视图 + 批量操作
2. 讨论协作增强（`@提及 + 草稿恢复 + 提醒`）
3. 资料库结构化升级（标签 / 关联 / 版本）

这 3 个方向对现在的元策最能直接提升“日常可用性”和“团队协作效率”。
