# fix: 恢复项目新增成员批量选择语义

## 目标

恢复旧版项目成员新增的用户可见结果：项目负责人或项目管理员只能从已启用、尚未加入该项目的用户中搜索并多选成员，以统一角色一次加入；Web 与 Desktop 共享同一交互和 API 契约。

## 已确认差异

- 旧版项目详情在服务端排除已有成员，仅展示已启用候选用户及其系统角色。
- 旧版弹窗支持按姓名、用户名或角色搜索、勾选多个用户，并在未选择时禁止提交。
- 当前共享应用退化为手工填写单个用户名，既缺少候选范围，也不支持批量加入。

## 范围

- 在 API 增加候选成员读取与批量新增契约，保留既有单成员 `POST /members`。
- 在共享 API client、SharedApp 和 Desktop 受限 transport 接入新契约。
- 补 API、共享 client、Web E2E 与 Desktop operation 映射测试，并更新 OpenAPI。

## 非目标

- 不改变项目成员角色、移除成员、项目负责人转移或系统用户页的项目分配语义。
- 不恢复 Askama 模板或旧静态脚本。

## 执行单元

### U1：服务端与平台契约

- 提供只返回已启用且尚未加入目标项目的候选用户接口，复用项目成员管理权限边界。
- 提供批量加入接口；用户名去重、空选择和无效用户全部在写入前校验，成功时为每位用户保留成员与项目动态事实。
- 将新读取与写入 operation 纳入 Desktop 受限 transport，并同步 OpenAPI。

### U2：共享成员选择器

- 打开弹窗时读取候选用户；展示搜索、选择计数、候选用户的姓名/用户名/系统角色和空态。
- 以单次批量请求提交选中用户及角色；成功后刷新项目详情、成员、候选集和顶部状态。
- 维持提交锁、失败反馈和关闭弹窗的既有语义。

### U3：验证与复核

- 覆盖候选集过滤、批量请求体、权限拒绝、空选择、成员刷新和 Desktop operation 映射。
- 运行聚焦 Rust、前端、Web E2E 与 Desktop 检查，并在 review 中记录旧版对照与验证结论。

## 验收标准

1. 已存在成员和已停用用户永不出现在候选列表中。
2. 管理者可搜索并一次选择多个候选用户，未选择时不能提交。
3. 所选用户以同一项目角色加入，成员表、候选列表和顶部状态立即刷新。
4. 无权限用户不能读取候选集或执行批量加入；Desktop 与 Web 使用相同 API 语义。
