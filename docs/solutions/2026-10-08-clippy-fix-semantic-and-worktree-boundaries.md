# Clippy 自动修复的语义与构建隔离

`cargo clippy --fix` 的建议仍需差异审查与运行验证。遇到 `serde_json::Value` 与 `String` 比较，不应直接按 `cmp_owned` 建议改成与原数字比较：HTTP请求头在JSON中是字符串，`Value` 的字符串和数字比较语义不同。将预期字符串预先计算，再用 `as_str()` 明确类型，可以消除告警而保留合同。

浮点比较也不能只按直觉简化：`!(hours > 0.0)` 会拒绝NaN，而 `hours <= 0.0` 不会。使用 `partial_cmp` 明确不可比较的结果，验证NaN、无穷、零、负数与合法上下界。

库的告警消除后，应继续检查 `--all-targets`；集成测试辅助函数的参数数量、跨await持有同步锁等告警可能到这时才完整显现。

隔离worktree用于基线复现时，应使用各自的构建target目录，尤其在内部函数签名不同的情况下。本轮共用target曾导致主树测试误复用基线库签名；结束基线任务后，定向清理API开发构建缓存并从主树重跑验证解决，不需要回滚源码。不要把这种构建产物冲突误判为产品回归。

现有HTML清洗测试应验证安全合同与合法系统属性，而非精确要求无属性标题；章节标识功能启用后，原 `<h2>文本</h2>` 的精确字符串断言会过期。修正时须保留脚本、事件属性和危险URL被清除的断言。
