# SSE 失效通知与局部最终事实刷新

## 问题

多人协作页面收到评论、流转或附件变化后，如果直接整页重载，会造成 loading 闪烁、组件重挂和本地草稿丢失；如果在客户端按事件内容增量 patch，又容易与权限、附件状态和并发写入后的服务端最终事实漂移。

## 可靠模式

把 SSE 事件视为“当前聚合数据已失效”，不视为完整业务状态：

1. EventSource adapter 只接受固定路径和 allowlist 事件，并把宿主 payload 规范化为带 `itemKey`、`connectionId`、`sequence` 的事实。
2. 共享 coordinator 丢弃错误工作项、重复、乱序和已 dispose 连接的事件；刷新期间的新失效合并为至多一次尾随刷新。
3. 刷新只读取受影响的详情、评论和附件最终事实，不切换整页 loading，不替换页面根节点。
4. 异步写回前再次核对当前 route 和 item key，防止旧请求覆盖快速切换后的页面。
5. 服务端事实与编辑器草稿分开保存；局部刷新只更新服务端快照，不重置新增、编辑或回复草稿。

typing 等临时 presence 使用独立控制器：首次 focus 发送 active，持续输入按低于服务端 TTL 的间隔续期，空闲、blur、路由离开和卸载尽力发送 inactive。presence 失败静默降级，不进入正式 mutation 的全局错误提示。

## 验证模式

- 单测覆盖 item 隔离、connection sequence、刷新合并、续期节流、空闲停止和 dispose 幂等。
- 受控 EventSource E2E 保留页面节点标记和本地草稿，触发失效后断言只更新服务端内容。
- SPA 切换工作项后继续向旧 source 发送迟到事件，断言旧 source 已关闭且新页面无污染。
- 宿主能力使用显式布尔标记；共享 client 中存在方法不等于宿主 transport 支持该能力。

## 适用范围

适用于评论流、通知、状态面板和其他“事件只说明数据已变化”的协作界面。不适用于必须逐事件结算、不可重新读取最终事实的账务或日志消费链路。

## 当前边界

进程内广播只适合单 API 实例。扩展为多实例时，应替换服务端事件总线，但客户端的失效通知、局部读取和草稿隔离模式可以保持不变。
