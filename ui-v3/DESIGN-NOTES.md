# 元策 UI v3 · 设计决策记录

记录 v3 原型的设计依据、被否决的方向与理由。供设计评审与后续 React 回迁时查阅。

## 一、检索来源

使用本机 `ui-ux-pro-max` 技能检索，命令与结果如下。

### 1.1 技能可用性说明

本机技能库（`skm list`）中与界面设计相关的只有 `ui-ux-pro-max`，没有其它同类 UI 设计技能。
`ui-v3/` 的视觉决策全部基于该技能的检索结果 + 人工过滤，未依赖外部素材。

### 1.2 设计系统（`--design-system`）

```bash
python3 "$HOME/.skills-manager/skills/ui-ux-pro-max/scripts/search.py" \
  "modern saas team collaboration project management workspace clean refined" \
  --design-system --variance 5 --motion 5 --density 6 -p "YuanCe V3 Refined"
```

命中与采纳情况：

| 检索输出 | 采纳 | 理由 |
|---|---|---|
| COLORS: Primary `#6366F1`、Secondary `#818CF8`、Accent `#059669`、Background `#F5F3FF`、Border `#E0E7FF`、Destructive `#DC2626` | 采纳 | 靛蓝主色 + 翡翠强调的结构被完整采用（色值按可读性微调，见下表） |
| STYLE: 检索给出 `Data-Dense Dashboard` 与 `Motion-Driven` 两种 | 部分采纳 | 采纳数据密集的信息结构与微交互；否决重编排的入场动画（见 2.3） |
| COLORS 字段异常：`Foreground` 与 `Card Foreground` 均输出 `#1E1B4B`（品牌深紫） | 否决 | 正文前景色应为中性深色，属检索输出异常，未照抄 |
| TYPOGRAPHY: `Plus Jakarta Sans` | 否决 | 见 2.2 |
| MOTION: GSAP `Stagger List` | 否决 | 见 2.3 |
| PATTERN: `Trust & Authority + Conversion`（Hero、案例、定价、CTA） | 否决 | 见 2.1 |
| AVOID: `Static design` | 采纳 | 第一版原型过于静态（满屏细线、无动效），第二版补上卡片悬浮、导航态过渡与入场位移 |

### 1.3 配色检索（`--domain color`）

查询 `saas dashboard indigo violet accent teal sidebar` 与 `project management tool kanban status colors`，
命中 `Micro SaaS`（靛蓝 + 翡翠）与 `SaaS (General)`（蓝 + 橙）两套。采纳前者的靛蓝主色。

### 1.4 UX 规则（`--domain ux`）

查询 `dense data table filtering bulk selection scanning` 与 `sidebar navigation hierarchy workspace app switching`，采纳：

- **批量操作**：列表需支持多选 + 批量操作，采用「勾选列 + 操作条」形态。
- **表格溢出**：宽表必须包在横向滚动容器内。
- **字号刻度**：使用模块化刻度，禁止随手取值。
- **面包屑**：3 层以上深度需显示位置。
- **键盘导航**：可操作控件全部键盘可达，焦点可见，tab 顺序与视觉顺序一致。
- **标题层级**：h1 → h2 → h3 连续，不跳级。

### 1.5 预交付检查清单

已全部落地：SVG 图标（无 emoji）、hover 态（130–200ms）、正文对比度 ≥ 4.5:1、焦点态可见、
`prefers-reduced-motion` 生效、375/768/1024/1440 四档响应式。

## 二、被否决的方向

### 2.1 营销站式布局（`Trust & Authority + Conversion` / `Enterprise Gateway`）

检索给出的 pattern 是面向外部获客的营销站：Hero、案例、定价、CTA、Logo 轮播。

否决理由：元策是内部协作工作台，核心用户是研发与产品团队，首要目标是「快速定位并处理工作项」，不是获客转化。
Hero 与案例区会挤占首屏空间并降低信息密度。

实际采纳：把检索推荐的 mega menu 思路落地为**左侧固定深色侧栏的分组导航**（概览 / 项目 / 交付 / 协作 / 系统），
而不是悬停展开的下拉。

### 2.2 等宽字体作为正文（`Fira Code` / `Fira Sans` / `Plus Jakarta Sans`）

检索建议把 Fira Code 或 Plus Jakarta Sans 作为主要字体族。

否决理由：
1. 等宽字体的首要用途是代码与编号，本产品正文是中文长句与表格文本，等宽会显著降低中文可读性。
2. 这两个字族都不含中文字形，回退到系统中文字体后，西文与中文混排的基线与字重都会失衡。
3. Plus Jakarta Sans 需要从 Google Fonts 引入，桌面端与离线环境不可靠。

实际采纳：字体栈为 `-apple-system / PingFang SC / Microsoft YaHei / Source Han Sans SC` 系统栈，
等宽字体只用于工作项编号、存储前缀这类确实需要等宽对齐的场景（`--font-mono`）。

### 2.3 GSAP 编排动画（`Stagger List`）

检索给出的动效方案是加载时错峰入场动画，并附了 GSAP 代码片段。

否决理由：
1. 本模块的技术前提是零依赖纯 HTML + CSS + JS，引入 GSAP 与该前提直接冲突。
2. 内部工作台的首屏是数据表与列表，几十行错峰入场会拖慢「看到数据」的时间，对每日高频使用是反复的视觉噪音。

实际采纳：只保留功能性微交互 —— 卡片悬浮上浮、导航态过渡、抽屉滑入、表格行 hover，
以及页面级 320ms 的入场位移（`--motion-slow`），全部在 `prefers-reduced-motion` 下降为 0.01ms。

### 2.4 检索配色输出中的字段异常

`--design-system` 的配色段落中，`Foreground` 与 `Card Foreground` 均输出为 `#1E3B4B`（品牌深色），
而正文前景色应接近中性深色。这是检索输出的字段异常，**未照抄**。

实际采纳：文字前景色自定义为 `#151827`（17.6:1）、`#4f5568`（7.4:1）、`#676d7f`（5.2:1）三级，
全部经逐对核验达到 4.5:1。

## 三、最终设计系统

### 3.1 颜色

色系经过一次收敛：初版靛蓝 + 渐变 + 彩色磁贴被判「太骚」，改为深灰蓝 + 纯色 + 单色磁贴。

| 角色 | 取值 | 说明 |
|---|---|---|
| 主色 | `#2f5d8f`（深灰蓝） | 主按钮、选中态、链接 |
| 深色区主色 | `#3f719f` | 侧栏品牌标识 |
| 页面底色 | `#f2f4f6` | 中性冷灰，无紫调，白卡片浮于其上 |
| 承载面 | `#ffffff` / `#fafbfc` / `#eff2f4` | 卡片 / 次级分区 / 表头与凹陷面 |
| 侧栏 | `#1b2028 → #232a35` | 深色中性灰蓝，与浅色内容区形成对比 |
| 文字 | `#16191f` / `#4d545e` / `#666d78` | 正文 / 次要 / 弱化，全部 ≥ 4.5:1 |
| 状态 | 翡翠 `#2e7d5b`、琥珀 `#8a6a24`、砖红 `#a5433c`、蓝 `#2f5d8f`、灰紫 `#655891`、青 `#2b7168` | 每个状态一套「底色 + 边框 + 文字」三元组，整体降饱和 |
| 指标磁贴 | `#eff2f4` 底 + `#5a626d` 图标 | 默认单色，只有告警项上语义色 |

收敛要点：
- **取消全部渐变**：品牌块、项目色块、进度条、趋势柱一律纯色。
- **指标磁贴单色化**：一行 KPI 原本是紫/橙/绿/红四色，改为单色 + 仅告警项着色。
- **状态色降饱和**：保留色相以便扫读，但把底色压到很浅、彩度降低。
- **去掉紫调**：页面底色与侧栏都回到中性冷灰，避免靛紫在整屏上的视觉噪音。

### 3.2 层次与质感

- 不用满屏描边建立层级，改为**留白 + 柔和阴影**：卡片 `0 1px 2px / 0 2px 6px`，悬浮时 `0 8px 20px`。
- 圆角统一为 8 / 10 / 14 / 18 四档，卡片 14，按钮与输入 8。
- 页面底色带微紫倾向，白卡片与深色侧栏形成两个视觉锚点，页面不再是一片灰白。

### 3.3 字号与密度

- 页面标题 22px / 700，卡片标题 15px / 600，正文 14px，元信息 12–13px。
- 表格行高 46px，表头 40px，输入控件 36px。
- 关键数字用等宽数字（`tabular-nums`），保证列表纵向对齐。

### 3.4 颜色不单独承载语义

状态用「圆点 + 文字」双通道，优先级用「形状 + 文字」表达，未读用「未读」文字标签 + 强调色。
灰度打印或色觉障碍场景下信息不丢失。

### 3.5 组件形态

- 指标卡：彩色图标磁贴（42px 圆角方块）+ 28px 数字 + 变化说明，悬浮上浮 2px。
- 项目列表：**卡片网格**而非大表格，每张卡含首字母色块、名称、编号、状态胶囊、待处理拆分与成员头像组。
- 列表页：勾选列 + 批量操作条（默认隐藏）+ 状态胶囊 + 形状优先级。
- 详情页：主栏（描述 / 讨论 / 附件）+ 右侧属性栏分栏。

## 四、v3 相对现网的设计取舍

| 取舍点 | 选择 | 理由 |
|---|---|---|
| 导航形态 | 顶部横排 → 左侧固定深色侧栏 | 现网一级导航已达 9 项（含「系统管理」下拉与桌面端下载），横向排列已接近上限；深色侧栏同时解决顶栏拥挤与页面缺少视觉锚点两个问题 |
| 品牌色 | 灰蓝 `#376b9b` → 深灰蓝 `#2f5d8f` | 比现网更沉稳，兼顾辨识度与长时间阅读的舒适度；比中间试过的靛蓝 `#4f46e5` 克制得多 |
| 页面底色 | 灰蓝 `#edf1f5` → 中性冷灰 `#f2f4f6` | 纯灰底让白卡片失去体积感，微冷灰底让卡片自然浮起又不喧宾夺主 |
| 层次表达 | 描边 → 阴影 + 留白 | 满屏细线是上一版最大的问题，视觉上像一张 Excel 打印稿 |
| 项目列表 | 大表格 → 卡片网格 | 项目是有封面感、有头像组、有统计摘要的实体，卡片比表格更易扫读 |
| 状态色 | 圆点为主 → 圆点 + 文字胶囊 | 现网部分状态仅靠颜色表达 |
| 批量操作 | 无 → 勾选列 + 操作条 | 检索 UX 规则明确要求 |
| 深色主题 | 暂不产出 | 现网 `frontend/packages/ui/src/styles.css` 已有 `html[data-theme="dark"]` 令牌；v3 先把浅色基调定稿，深色作为后续派生 |

## 五、待决事项

1. **浅色基调是否定稿**：当前版本已按「深色侧栏 + 靛蓝主色 + 卡片化」的现代工作台方向成型，
   若评审倾向更保守的企业风，改动集中在色彩与阴影，布局与组件形态可保留。
2. **深色主题**：待浅色定稿后派生，颜色令牌需要补一组暗色值。
3. **回迁路径**：设计定稿后，`frontend/packages/ui` 需要按本模块的令牌表与组件规格重写，
   并同步更新 `frontend/parity/main-web-visual-contract.json` 与体验清单。
